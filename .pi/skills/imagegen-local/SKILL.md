# imagegen-local

把用户的自然语言生图意图 → 脚本参数 → **串行**执行 → 回报图片路径。

自包含技能：脚本和事实文档都在本技能目录内，不依赖宿主项目的目录结构。

## 前置条件

1. 本地 mlx-serve 已启动，图像模型已加载：

   ```bash
   curl -s http://127.0.0.1:11234/v1/models
   ```

2. 默认模型为 `ddalcu/Qwen-Image-2.1-MLX-Serve-4bit`，`capabilities` 需包含 `image`。

## 资源

| 文件 | 何时读 |
|---|---|
| `scripts/mlx_image_gen.py` | 要确认参数、默认值、报错行为时；改动前必读，不要凭记忆写参数 |
| `references/script-reference.md` | 需要参数表、耗时预算、报错对照时 |
| `references/mlx-serve-api.md` | 用户要求脚本未支持的能力（负向提示词、CFG、LoRA、图生图），或排查接口层问题时 |

脚本与两份 reference 是事实来源，彼此冲突时以 `scripts/mlx_image_gen.py` 的**实际代码**为准。

## 硬性约束

1. **禁止并发**：任一时刻只允许一个生图进程在跑。不要并行发起工具调用，不要用 `&`、`xargs -P`、多终端同时跑。
2. **多图必须串行排队**：N 张 = N 次顺序调用，前一张返回后再开始下一张。
3. **批量生成必须显式指定互不相同的 `--output`**：脚本默认命名只精确到分钟（`output/mlx_image_gen_YYYYMMDDHHMM.png`），同分钟内多次生成会互相覆盖。
4. **不许编造脚本没有的参数**：脚本只暴露 `-p/--url/--model/--size/--steps/--seed/--transparent/--output/--timeout`。用户要 `negative_prompt`、`cfg_scale`、LoRA、图生图时，如实说明当前不支持，并说明需要改脚本（改法见 `references/mlx-serve-api.md`）。
5. **不许用 Pillow / SVG / HTML 等替代生图**，也不要伪造或复述不存在的图片路径。

## 执行流程

### 1. 前置检查（每轮对话首次生成前做一次）

```bash
curl -s -m 5 http://127.0.0.1:11234/v1/models
```

- curl 失败 → mlx-serve 没启动，告知用户启动服务，不要反复重试。
- 模型列表里没有默认模型 → 取 `capabilities` 含 `image` 且 `loaded: true` 的 id，用 `--model` 传入。

### 2. 意图 → 参数

不确定的项一律用脚本默认值，不要主动改 `--size`/`--steps`。

| 用户说法 | 映射 |
|---|---|
| 没提尺寸 | 不传 `--size`（默认 720x720） |
| 横图 / 16:9 / 宽幅 | `--size 1280x720`（必须是 16 的倍数） |
| 竖图 / 手机壁纸 | `--size 720x1280` |
| 更清晰 / 高质量 | `--size 1024x1024`（保持默认步数）；单张约 20 分钟，**先跟用户确认再跑** |
| 快点 / 草稿 | `--size 512x512 --steps 8~15`（约 1.5~2.5 分钟） |
| 透明背景 / 贴纸 / 免抠 | 加 `--transparent`，**且提示词里必须写明透明背景** |
| 复现之前那张 | `--seed <相同数值>`（默认 42 本身可复现） |
| 多变体 / 每张不同 | 串行 N 次，每次换 `--seed`，显式给不同 `--output` |
| 指定文件名或位置 | `--output <路径>` |

尺寸宽高必须是 16 的倍数：服务端会把非倍数尺寸向上对齐（实测 712 → 720），所以直接给 16 的倍数。

**提示词处理**：模型对英文提示词效果更好。用户用中文描述时，改写成英文再传给 `-p`，保留主体、风格、光线、构图、材质等关键要素，不要自行加戏或删减核心主体。开 `--transparent` 时提示词里要有 `transparent background` 之类的表述——该参数只保留模型输出的 alpha 通道，不会自动抠图。

### 3. 调用脚本

优先用技能自带脚本，保证在任何项目里都能跑：

```bash
python3 <skill>/scripts/mlx_image_gen.py -p "<英文提示词>" [其他参数]
```

若宿主项目里自带同名脚本（例如 `src/mlx_image_gen.py`）且参数更全，则改用它，并在改完后同步本技能的副本。

- 进度条在 stderr，成功时 stdout 打印 `图片已保存到：<路径>`，失败退出码 1。
- **耗时**：单张 ≈ 步数 × 每步秒数（Apple M4 / 24 GB 实测：512x512 约 10 s/步，720x720 约 17~21 s/步，1024x1024 约 40 s/步）。默认参数单张 **8~9 分钟**。换机器需重测，详见 `references/script-reference.md`。
- bash 的 `timeout` 按上面估算给足（单张默认 600s 打底，批量按张数累加再乘 1.5）。
- 若单次工具调用有超时上限，改成一次调用只跑一张；生成期间不要为了"看着有进展"重复发起请求。
- 客户端中断后服务端会立即回到空闲，超时后重试是安全的，不必等冷却。
- 单张请求可直接用默认输出路径；只有用户明确要文件名时才传 `--output`。

### 4. 多图：串行批次模板

一次 bash 调用里用循环跑完整批，天然串行，不要拆成并行调用：

```bash
ts=$(date +%Y%m%d%H%M%S)
i=0
for p in "<英文提示词1>" "<英文提示词2>"; do
  i=$((i + 1))
  python3 <skill>/scripts/mlx_image_gen.py -p "$p" --seed $((42 + i)) \
    --output "output/batch_${ts}_$(printf '%02d' "$i").png"
done
```

### 5. 校验与回报

生成后逐张确认文件存在：

```bash
ls -l <输出路径>
```

回报内容：

- 每张图的路径
- 参数摘要：`size` / `steps` / `seed` / `transparent`
- 失败时说明原因与建议，不要静默跳过

## 失败处理

| 现象 | 处理 |
|---|---|
| HTTP 502 | 本机 VPN / 反向代理拦截了本地请求，让用户关闭 VPN 后重试 |
| HTTP 503 | 显存不足或模型未加载，不要自动重试，报告给用户 |
| HTTP 400 | 参数不合法；`transparent` 只支持 Qwen-Image-2.1 |
| HTTP 404 | 模型 id 不存在，用 `/v1/models` 里的 id |
| 退出码 1 + `接口返回 HTTP ...` | 读 stderr 里的原始响应体，转述给用户 |

完整状态码与接口字段见 `references/mlx-serve-api.md`。
